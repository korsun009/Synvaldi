# Адаптер Vivaldi для Windows

Расширение Manifest V3 связывает один профиль Vivaldi с приложением Synvaldi через Native Messaging. Для каждого профиля расширение хранит собственный UUID. Нужные разрешения перечислены в манифесте. Доступ к содержимому страниц, паролям, cookies и истории браузера не требуется.

## Установка

Установи настольное приложение. В нужном профиле открой `vivaldi://extensions`, включи режим разработчика, нажми «Загрузить распакованное расширение» и выбери установленный каталог расширения с файлом `manifest.json`. Открой параметры Synvaldi на этой странице, чтобы проверить соединение с настольным приложением. При использовании нескольких профилей повтори подключение в каждом нужном профиле.

ID расширения — `jcfipkamaklpdghopicgfllhnigfjcio`. Настольный установщик регистрирует для этого ID локальный хост `com.synvaldi.bridge`. Подтверждение установки делает владелец браузера. Сборки в Chrome Web Store пока нет. Для обычной работы отладочный порт не требуется. [Расширения в Vivaldi](https://help.vivaldi.com/desktop/appearance-customization/extensions/) · [Native Messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)

## Обычные вкладки

При явном выборе всех обычных вкладок модуль отслеживает создание, закрытие, навигацию, перестановку, закрепление и перенос между окнами. Передаётся полный HTTP(S)-адрес, включая query и fragment. Приватные окна, внутренние страницы, файлы и URL со встроенными логином или паролем исключены. В URL обычной страницы могут содержаться личные данные, заданные самим сайтом.

Удалённая навигация обновляет уже сопоставленную вкладку. Новая вкладка открывается фоновой. Для отдельного исходного окна создаётся отдельное свёрнутое окно. При закрытии последней вкладки сохраняется локальная пустая страница. Явная команда «Продолжить» может активировать окно и вкладку. Для текущего сеанса мониторятся события штатного API. После перезапуска связь восстанавливается по UUID окна Vivaldi, точному URL и позиции вкладки в окне. Изменение одновременно этих признаков при закрытом браузере может привести к выдаче нового идентификатора.

Локальная очередь хранится в `chrome.storage.local` до подтверждения приложения. Подтверждение входящих вкладок выдаётся после повторного чтения и сверки. При обрыве соединения расширение пробует подключиться снова через 30 секунд. Снимок с сообщением Native Messaging размером свыше 950 000 байт возвращает ошибку. Пакеты локальных изменений разбиваются на части. [Chrome Tabs API](https://developer.chrome.com/docs/extensions/reference/api/tabs/) · [Windows API](https://developer.chrome.com/docs/extensions/reference/api/windows/)

## Выбор рабочих пространств

Для Windows Vivaldi 8.3.4191.35 проверен перенос выбранных пространств при закрытом профиле. Модуль `ColdWorkspaces` читает каталог `vivaldi.workspaces.list` из Preferences и новейший файл `Sessions/Session_*` формата SNSS v3. Из навигации передаётся только разрешённый текущий URL. При импорте модуль создаёт записи навигации с пустыми полями page state, заголовка и referrer. В архиве на сервере отсутствуют локальная история переходов, содержимое форм и бинарные файлы SNSS.

В каждом передаваемом пространстве сохраняются его ID, название, значок, эмодзи, идентификаторы окон и вкладок, URL, относительный порядок внутри окна, закрепление, название и цвет стопки. Для раскладки обрабатываются ID, layout, type и индекс плитки. Если все участники раскладки входят в выбранное пространство, переносятся также дерево деления, горизонтальные и вертикальные направления и доли вручную перемещённых границ. В контрольной раскладке на две панели штатный API открытого Vivaldi вернул деление 37/63. После штатного выхода снимок сохранил точное дерево, прежние идентификаторы, название стопки и порядок вкладок. Проверялись хранимые параметры раскладки. Пиксельные размеры зависят также от размеров окна и масштаба на конкретном ПК.

Удаление выбранного пространства очищает его перенесённые веб-вкладки. Локальные вкладки с неподдерживаемыми адресами возвращаются в основное пространство. Не выбранные пространства сохраняются. Восстановление вкладок из SNSS при следующем обычном запуске зависит от настройки Vivaldi «При запуске → Последняя сессия».

При записи применяется только выбранный каталог. Оригиналы изменённых файлов хранятся в `Synvaldi Backups/<идентификатор операции>` внутри каталога профиля. Перед заменой модуль повторно разбирает подготовленную сессию и сверяет её со снимком. Журнал и контрольные суммы позволяют распознать прерванную замену двух файлов. При конфликте с более свежими файлами автоматическое восстановление останавливается. Чтение доступно в 8.3.4191.30/35, запись проверена и включена в 8.3.4191.35. Модуль принимает записи навигации с однозначным текущим индексом. Для последующих патчей той же ветки Vivaldi и Chromium проверяются SHA-256 трёх ресурсов установленного браузера, которые отвечают за рабочие пространства и их параметры. Совпадающий набор принимается автоматически. При смене формата ожидается обновление адаптера. При переносе вкладки между двумя выбранными пространствами сохраняется её UUID. Попытка забрать вкладку из невыбранного пространства отклоняется. [Официальное описание переноса данных при закрытом Vivaldi](https://help.vivaldi.com/desktop/tools/import-and-export-browser-data/) · [Формат навигации Chromium](https://chromium.googlesource.com/chromium/src/+/main/components/sessions/core/serialized_navigation_entry.cc)

**Живой выбор пространства пока недоступен.** На обеих проверенных сборках обычный контекст расширения получает из `chrome.tabs` URL, окно и порядок. Запросы `workspaceId` и `vivExtData` через `tabs.query` отклоняются. В ответах `tabs.get/query` эти данные отсутствуют. Обновление служебных данных Vivaldi вызывает `onUpdated` с пустым набором изменений. Экспериментальная запись `vivExtData` сохраняла системный `ext_id`, однако сохранение соседних пользовательских полей и группы не гарантировано.

На Windows работающий Vivaldi блокировал новое поколение SNSS с ошибкой sharing violation (32), включая открытие с `FileShare.ReadWrite | FileShare.Delete`. В том же каталоге старое поколение успешно читалось и содержало предыдущую сессию. По этой причине режим выбора пространств использует закрытый профиль. Расширение отказывается включать живое наблюдение в этом режиме. Один лишь выбор пространства не отправляет все вкладки браузера.

## Проверки

Для команд ниже нужен Node.js 24. Для холодного теста и теста Native Messaging нужен также .NET SDK 10. Тестовые профили создаются в новых каталогах внутри `SYNVALDI_TEST_ROOT`. При необходимости укажи путь к Vivaldi через `VIVALDI_EXE`. Активный пользовательский профиль для тестов не используется.

```powershell
node --test browser/tests/model.test.mjs
$env:SYNVALDI_TEST_ROOT = 'X:\DevData\Temp\Synvaldi-tests'
node browser/tests/vivaldi.integration.mjs
$env:SYNVALDI_TEST_NATIVE = '1'
node browser/tests/vivaldi.integration.mjs
node browser/tests/cold.integration.mjs
```

Обычный сценарий использует два экземпляра Vivaldi и проверяет перенос точного URL, закрепление и положение, два окна, повторную доставку, обновление текущей вкладки и закрытие. Сценарий Native Messaging собирает тестовую копию штатного нативного хоста с отдельным именем канала, регистрирует временное уникальное имя в HKCU и удаляет регистрацию после проверки. Он проверяет реальные события расширения, кадры нативного канала, отсутствие эха и сохранение фокуса окна. Холодный тест создаёт профиль с тремя вкладками в двух пространствах, проверяет избирательный импорт, повтор операции, удаление каталога, неподходящий URL, снимок при блокировке, запуск браузера и повторный захват после выхода.
