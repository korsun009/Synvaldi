# Защищённый вход

Стандартный Compose публикует API только на loopback, PostgreSQL доступен внутри проекта. Дополнительный gateway обслуживает выбранный адрес защищённой сети устройства, например Tailscale. Перед запуском проверь, что адрес принадлежит VPN-интерфейсу и порт 48184 свободен. Разрешения на вступление в сеть задаются средствами VPN. Аккаунты Synvaldi дополнительно изолируют профили.

Для развёртывания сначала подготовь пароль по инструкции в server/README.ru.md. Укажи SYNVALDI_TLS_DIR с файлами cert.pem и key.pem, SYNVALDI_CADDYFILE с абсолютным путём deploy/Caddyfile и SYNVALDI_TUNNEL_IP с адресом интерфейса. Сертификат должен содержать SAN фактического адреса. Хорошо защищённый родительский каталог нужен как для TLS-ключа, так и для пароля базы.

```sh
docker compose -p synvaldi -f server/compose.yaml -f deploy/tunnel.compose.yaml up -d --build
curl --cacert /path/to/cert.pem https://PRIVATE-TUNNEL-ADDRESS:48184/health
```

Содержимое индивидуального файла подключения, который можно передать пользователю по доверенному каналу:

```json
{
  "Server": "https://PRIVATE-TUNNEL-ADDRESS:48184",
  "CertificateSha256": "UPPERCASE_SHA256_OF_LEAF_CERTIFICATE_DER"
}
```

При замене самоподписанного сертификата передай клиенту новый отпечаток. При использовании обычной доверенной цепочки работает штатная проверка TLS. Не загружай ключи и действующие профили подключения в публичный репозиторий.
